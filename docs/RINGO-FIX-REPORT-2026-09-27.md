# 링고 점검 후 수정·검증 결과

2026-09-27 기준. 이 문서는 `RINGO-AUDIT-2026-09-27.md`에서 확인한 문제와 후속 점검에서 발견한 기존 데모 데이터 문제의 처리 결과를 기록한다. 테스트 결제와 격리된 PGlite DB를 사용했으며 실제 결제사 환불·송금·메일 발송은 실행하지 않았다.

## 수정한 내용

| 범위 | 결과 |
|---|---|
| 주문·결제 상태 | 주문 생성과 쿠폰 사용량 검사를 한 트랜잭션으로 묶고 쿠폰 행을 잠갔다. 결제 성공·실패·취소·만료의 상태 변경을 잠금 및 조건부 갱신으로 보호했다. 이미 환불한 결제에 성공 콜백이 다시 와도 상태를 되돌리지 않는다. |
| 환불·대사 | PG 호출 전에 환불 작업을 선점하고 결제별 고정 멱등 키를 전달한다. 취소·만료 뒤 들어온 결제와 추가로 승인된 결제를 관리자 환불 목록에 표시한다. 추가 결제는 원래 구매 권한과 정산을 건드리지 않고 그 결제 건만 환불한다. 환불 처리 중이거나 추가 승인액이 남은 주문은 정산에서 보류한다. 환불 요청·거절에도 조건부 갱신을 적용했다. |
| 웹훅 | 결제사, 금액, 통화, 가맹점, 결제 참조를 대조한다. 아직 구현하지 않은 실제 PG 어댑터는 환경변수만으로 활성화되지 않으며 웹훅을 수락하지 않는다. |
| 강의·구매 자료 | 강의별 고정 ID와 기존 진도 이전을 적용했다. 판매 중인 강의의 각 차시에 본문·영상·소속 파일이 있는지 검사한다. 기존에 비어 있던 데모 강의 노트를 복구하고, 내용이 없는 기존 공개 강의는 신규 판매가 되지 않도록 초안으로 전환하는 마이그레이션을 추가했다. 기존 데모 구매자가 파일을 받을 수 있도록 샘플 PDF를 채웠고, 상품 설명에 데모 자료임을 명시했다. |
| 목록·파일·운영 | 잘못된 페이지 번호를 첫 페이지로 정규화하고 로컬 영상 다운로드에 HTTP Range 응답을 지원한다. 다중 서버의 요청 제한 카운터를 PostgreSQL에 공유한다. 기존 Quick Tunnel 주소가 설정에 남아도 현재 터널로 접속한 요청의 링크를 사용한다. 한국어 주문 상품명 스냅샷을 저장·표시한다. |
| UI/UX | 관리자·판매자 메뉴의 숫자 알림은 작은 `N`으로 표시한다. 모바일 메뉴의 열기·닫기 포커스, Tab 제한, Esc 닫기, 배경 비활성화를 보강했다. `메인으로`와 프로필은 스크롤되는 메뉴와 분리해 하단에 둔다. 모바일 로그인 줄바꿈을 줄이고 미구현 소셜 버튼은 숨겼다. 주요 화면의 로딩·오류 복구 화면과 폼의 필드 오류·미저장 경고를 추가했다. |

## 실제로 수행한 검증

- `npm run test:commerce`: 격리된 메모리 DB에서 17개 시나리오 통과. 쿠폰 경합, 중복 환불, 결제 상태 경합, 여러 승인 결제의 개별 환불, 정산 보류·차감, 빈 강의·진도 이전, 불일치 웹훅을 포함한다.
- `npm run test:routes`: 페이지 번호와 로컬 파일의 200/206/416 Range 응답 통과. 로컬 서버를 지정한 HTTP 페이지 번호 요청도 200을 확인했다.
- `npm run typecheck`, `npm run lint`, 격리된 DB·업로드 경로를 사용한 `npm run build` 통과.
- 로컬 브라우저에서 관리자·판매자·구매자 데모 로그인, 관리자 환불 목록, 구매자 강의 노트·다운로드 링크 표시를 확인했다. 390px 모바일 로그인 화면에서 상단 로그인 버튼이 한 줄로 보였다. 390×600 모바일 판매자 메뉴에서 닫기 버튼으로 포커스가 이동하고, Tab은 메뉴 안에 머물며 Esc 후 메뉴 열기 버튼으로 돌아왔다. 메뉴를 스크롤해도 `메인으로`·프로필 영역의 하단 위치가 600px로 유지됐다.
- 기존 로컬 PGlite 데이터에 마이그레이션을 적용한 뒤 강의 노트가 나타나고 데모 다운로드 파일이 보이는 것을 확인했다.

## 운영 전 별도 검증이 필요한 부분

- PearPay·NextPay 결제 생성/환불 API는 공식 계약 명세가 없어 구현할 수 없다. 현재는 의도적으로 비활성화되어 있다. 실제 PG 계약 문서, 테스트 자격 증명, 웹훅 서명·상태·취소 명세를 확보한 다음 샌드박스에서 결제와 환불을 검증해야 한다. 테스트 결제 시나리오가 실제 PG 처리를 증명하지는 않는다.
- 운영 PostgreSQL 다중 인스턴스, SMTP 전송, S3 파일 전송, 실제 카카오톡 앱의 공유 카드 캐시와 외부 터널 접근성은 이번 로컬 검증에 포함되지 않았다.
- 개발 브라우저에서는 확장 기능 등이 HTML에 주입한 것으로 보이는 `style="user-select:auto"` hydration 경고가 계속 관찰됐다. 서버 HTML과 앱 코드가 생성한 속성으로 확인되지 않았으므로 확장 기능을 끈 브라우저와 운영 빌드에서 따로 확인해야 한다. 개발용 Next.js 배지는 앱 오류 표시는 아니다.
- 데모 상품에 복구한 PDF는 기능 확인용 샘플이다. 실제 판매 전에는 판매자가 약속한 완성 파일·영상으로 교체해야 한다. 기존에 비어 있어 초안으로 전환된 강의는 콘텐츠를 채운 뒤 다시 심사·공개해야 한다.
